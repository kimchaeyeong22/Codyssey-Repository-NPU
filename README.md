# Mini NPU Simulator

## 1. 프로젝트 소개

Mini NPU Simulator는 Python을 이용하여 간단한 NPU(Neural Processing Unit)의 연산 과정을 모방한 콘솔 기반 시뮬레이터입니다.

두 개의 필터(Filter)와 입력 패턴(Pattern)을 대상으로 MAC(Multiply-Accumulate) 연산을 수행하고, 계산된 점수를 비교하여 입력 패턴이 어떤 필터와 더 유사한지 판정합니다.

이 프로젝트에서는 행렬의 크기를 3×3뿐만 아니라 5×5, 13×13, 25×25까지 확장하여 처리할 수 있도록 구현했습니다.

또한 JSON 파일을 활용한 테스트 데이터 관리, 입력 데이터 검증, 자동 테스트, 성능 측정을 통해 프로그램의 정확성과 효율성을 확인했습니다.

## 4. 핵심 구현 원리

### 4-1. MAC 연산 (Multiply-Accumulate)

MAC은 곱셈과 누적 덧셈을 수행하는 연산입니다.

입력 패턴과 필터의 같은 위치에 있는 원소를 각각 곱한 다음, 모든 결과를 더합니다.

수식으로 표현하면 다음과 같습니다.

\[
MAC(A,B)=\sum_{i=0}^{N-1}\sum_{j=0}^{N-1} A_{ij}\times B_{ij}
\]

예를 들어 다음과 같은 3×3 행렬이 있다고 가정합니다.

```text
입력 패턴       필터

1 2 3           1 2 3
2 2 2           2 2 2
1 1 1           3 3 3
```

같은 위치의 숫자를 곱하고 모두 더하면 MAC 점수가 계산됩니다.

### 4-2. 모드별 동점 처리 규칙

본 프로그램은 `epsilon` 값을 활용하여 두 필터의 MAC 점수가 사실상 동일한 경우를 동점으로 판정합니다.

```python
if abs(score_cross - score_x) < epsilon:
```

두 점수의 차이가 epsilon보다 작으면 특정 필터를 선택하지 않고 `UNDECIDED`로 처리합니다.

**① 대화형 모드**

사용자가 직접 입력한 행렬을 판정할 때 두 필터의 점수가 동점이면 `UNDECIDED`를 출력합니다. 이는 두 필터 중 어느 쪽이 더 유사한지 명확하게 구분할 수 없다는 의미입니다.

**② JSON 자동 테스트 모드**

JSON 테스트 케이스는 미리 지정된 정답 라벨(expected)을 기준으로 예측 결과를 검증합니다. 따라서 동점으로 인해 예측 결과가 `UNDECIDED`가 되면, `Cross` 또는 `X`로 지정된 정답 라벨과 일치하지 않으므로 해당 테스트는 `FAIL`로 처리됩니다.

**모드별 처리 차이의 목적**

대화형 모드는 사용자에게 판정 결과를 안내하는 것이 목적이므로 동점 상태를 그대로 보여줍니다. 반면 JSON 자동 테스트 모드는 정해진 정답과 예측 결과의 일치 여부를 검증하는 것이 목적이므로 `UNDECIDED`는 정답 불일치로 처리합니다.

이처럼 동일한 동점 판정 로직을 사용하되, 실행 모드의 목적에 따라 최종 결과 처리 방식을 구분하였습니다.

### 4-3. 필터 비교 및 분류

두 필터의 MAC 점수를 각각 계산한 후 더 높은 점수를 가진 필터를 선택합니다.

- Cross 점수가 높으면 `Cross`
- X 점수가 높으면 `X`
- 두 점수가 같으면 `UNDECIDED`

부동소수점 연산에서는 아주 작은 계산 오차가 발생할 수 있으므로 epsilon 값을 사용하여 동점을 판정합니다.

```python
epsilon = 1e-9
```

두 점수의 차이가 epsilon 이하이면 동점으로 처리합니다.

### 4-4. 시간 복잡도

MAC 연산은 행렬의 모든 원소를 한 번씩 순회합니다.

행렬의 크기가 N×N이라면 총 연산 횟수는 다음과 같습니다.

\[
N \times N = N^2
\]

따라서 MAC 함수의 시간 복잡도는 다음과 같습니다.

\[
O(N^2)
\]

행렬 크기가 커질수록 연산해야 하는 원소의 수가 제곱에 비례하여 증가합니다.

## 4-5. CPU와 NPU의 연산 방식 및 병목 비교

CPU와 NPU는 데이터를 처리하는 목적과 연산 구조에 차이가 있습니다.

1) CPU의 연산 방식

CPU(Central Processing Unit)는 다양한 종류의 명령을 처리하도록 설계된 범용 프로세서입니다.

복잡하고 다양한 명령을 순차적으로 처리하는 데 적합합니다.

여러 코어를 이용한 병렬 처리도 가능하지만, 기본적으로 범용적인 작업 제어와 실행에 초점을 둡니다.

프로그램의 흐름 제어, 조건문, 입력 처리 등 다양한 작업을 효율적으로 수행합니다.

2) NPU의 연산 방식

NPU(Neural Processing Unit)는 인공지능의 행렬 및 벡터 연산을 효율적으로 처리하도록 설계된 전용 프로세서입니다.

여러 곱셈과 누적 연산(MAC)을 병렬로 수행할 수 있도록 설계됩니다.

반복적인 행렬 연산을 효율적으로 처리하는 데 적합합니다.

대량의 데이터를 동시에 처리하여 인공지능 추론 과정의 연산 효율을 높일 수 있습니다.

3) CPU와 NPU의 차이

NPU가 모든 작업에서 CPU보다 빠른 것은 아닙니다. 단순한 작업이나 데이터 규모가 작은 경우에는 작업 분배와 데이터 전송에 필요한 비용 때문에 NPU의 이점이 줄어들 수 있습니다.

4) 병렬 처리의 이점

행렬 연산에서는 각 원소의 곱셈과 누적 작업 중 일부를 독립적으로 수행할 수 있습니다.

예를 들어 두 행렬의 같은 위치에 있는 원소끼리 곱하는 작업은 서로 독립적이므로 여러 연산 유닛에 나누어 처리할 수 있습니다.

순차 처리: 하나의 연산 흐름에서 원소를 차례대로 계산

병렬 처리: 여러 연산 유닛이 서로 다른 원소의 연산을 동시에 수행

기대 효과: 연산 유닛을 효율적으로 활용하여 전체 처리 시간 단축

다만 부분 연산 결과를 최종 점수로 합산하는 과정에서는 결과 취합과 동기화가 필요합니다.

5) NPU에서 발생할 수 있는 주요 병목 지점

NPU의 연산 성능은 연산 유닛의 속도만으로 결정되지 않습니다. 다음과 같은 요소가 전체 성능에 영향을 줄 수 있습니다.

메모리 대역폭: 연산에 필요한 데이터를 메모리에서 충분히 빠르게 공급하지 못하면 연산 유닛이 데이터를 기다리게 됩니다.

데이터 이동 비용: CPU와 NPU 사이에서 데이터를 주고받는 과정에 시간과 전력이 소모될 수 있습니다.

연산 유닛 활용률: 작업을 적절히 분배하지 못하거나 데이터 양이 적으면 일부 연산 유닛이 유휴 상태가 될 수 있습니다.

결과 취합 및 동기화: 병렬로 수행한 부분 연산 결과를 모으는 과정에서 추가 비용이 발생할 수 있습니다.

작업 분할 비용: 작은 작업을 지나치게 잘게 나누면 작업 분배와 관리에 드는 비용이 연산 이점보다 커질 수 있습니다.

6) 현재 Mini NPU Simulator의 구현 범위와 한계

현재 프로젝트는 Python의 중첩 반복문을 이용하여 MAC 연산을 수행하고, 두 필터의 점수를 비교하여 패턴을 분류합니다.

따라서 실제 NPU 하드웨어의 병렬 연산 구조를 구현한 것은 아니며, NPU에서 중요하게 사용되는 MAC 연산의 원리를 소프트웨어로 모방한 시뮬레이터입니다.

현재 구현의 한계와 향후 개선 방향은 다음과 같습니다.

현재 구현: Python 반복문을 이용한 순차적인 MAC 연산

병목 가능 지점: 행렬 크기 증가에 따른 반복 연산 횟수 증가 및 Python 반복문 실행 부담

향후 개선: NumPy 벡터화, 블록 연산, 병렬 처리 등을 적용하여 연산 효율 비교

추가 검토: 데이터 이동 시간, 메모리 사용량, 연산 유닛 활용률 등을 측정할 수 있는 실제 하드웨어 환경과의 비교

이를 통해 현재 시뮬레이터가 구현한 MAC 연산 원리와 실제 NPU 하드웨어의 병렬 처리 구조 사이의 차이를 이해할 수 있습니다.

## 5. 주요 기능

### 5-1. 사용자 입력 기능

사용자가 직접 필터 A, 필터 B, 입력 패턴을 입력할 수 있습니다.

- 3×3 행렬 입력
- 행마다 숫자 3개 입력
- 잘못된 입력 형식 검증
- 숫자가 아닌 값이나 잘못된 개수의 숫자 입력 시 재입력 요청
- MAC 점수 계산 및 결과 판정

### 5-2. JSON 데이터 처리

`data.json` 파일에서 필터와 테스트 패턴을 불러옵니다.

JSON 데이터는 다음과 같은 구조로 관리합니다.

```json
{
    "filters": {
        "size_5": {
            "cross": [],
            "x": []
        },
        "size_13": {
            "cross": [],
            "x": []
        },
        "size_25": {
            "cross": [],
            "x": []
        }
    },
    "patterns": {
        "size_5_1": {
            "input": [],
            "label": "x"
        }
    }
}
```

실제 행렬 데이터는 각 배열에 저장됩니다.

필터 이름에 포함된 크기 정보를 이용하여 입력 패턴에 맞는 필터를 선택합니다.

예를 들어 `size_13_1` 패턴은 13×13 크기의 행렬이므로 `size_13` 필터를 사용합니다.

### 5-3. 데이터 검증

JSON 파일에서 읽어온 행렬 데이터가 올바른 구조인지 확인합니다.

검증 항목은 다음과 같습니다.

- 행렬의 행 개수가 지정된 크기와 일치하는지 확인
- 각 행의 열 개수가 지정된 크기와 일치하는지 확인
- 각 원소가 숫자형 데이터인지 확인
- 필터와 패턴 데이터가 올바르게 구성되어 있는지 확인

### 5-4. 라벨 표준화

JSON 데이터에 저장된 라벨을 프로그램 내부에서 일관되게 사용하도록 변환합니다.

| JSON 라벨 | 표준 라벨 |
|---|---|
| `+` | `Cross` |
| `cross` | `Cross` |
| `x` | `X` |

이를 통해 대소문자나 기호 차이로 인해 테스트 결과가 잘못 비교되는 문제를 방지합니다.

### 5-5. normalize_label 함수 분리의 설계 목적

`normalize_label()` 함수를 별도로 분리한 이유는 코드의 유지보수성과 재사용성을 높이기 위해서입니다.

- **유지보수성:** 라벨 변환 규칙이 변경되거나 새로운 라벨 형식이 추가되더라도 해당 함수만 수정하면 되므로 여러 코드 위치를 일일이 수정할 필요가 없습니다.
- **재사용성:** JSON 데이터의 정답 라벨과 필터 키 등 여러 위치에서 동일한 표준화 함수를 호출하여 일관된 변환 결과를 얻을 수 있습니다.
- **코드 가독성:** 라벨 변환이라는 하나의 역할을 독립된 함수로 분리하여 전체 프로그램의 구조를 이해하고 관리하기 쉽게 만들었습니다.

이러한 함수 분리는 각 함수가 하나의 명확한 책임을 담당하도록 하는 단일 책임 원칙(SRP)을 적용한 사례입니다.

### 5-6. 새로운 라벨 추가 절차

새로운 필터 라벨을 추가할 경우 코드, JSON 데이터, 자동 테스트가 서로 일치하도록 다음 순서로 작업합니다.

**① 라벨 정규화 함수 수정**

`main.py`의 `normalize_label()` 함수에 새로운 라벨의 변환 규칙을 추가합니다.

## 8. MAC 성능 측정 결과

## 8-1. 대규모 행렬 처리 시 성능 최적화 전략

현재 프로그램은 중첩 반복문을 사용하여 행렬의 각 위치에서 곱셈과 누적 연산을 수행합니다. 행렬 크기가 커질수록 연산해야 하는 원소의 수가 증가하므로 실행 시간과 메모리 사용량도 증가할 수 있습니다.

대규모 행렬을 효율적으로 처리하기 위해 다음과 같은 최적화 전략을 고려할 수 있습니다.

1) 벡터화(Vectorization)

현재는 Python의 반복문을 사용하여 각 원소를 하나씩 계산합니다. NumPy와 같은 수치 연산 라이브러리를 활용하면 행렬 전체에 대한 곱셈과 합산을 한 번에 처리할 수 있습니다.

기존 방식: 중첩 반복문으로 각 원소를 순차적으로 계산

개선 방향: NumPy의 배열 연산을 활용하여 반복문 실행 부담 감소

기대 효과: 대규모 행렬에서 연산 속도 향상

2) 블록 연산(Block Processing)

행렬 전체를 한 번에 처리하는 대신 일정한 크기의 작은 블록으로 나누어 연산하는 방법입니다.

큰 행렬을 작은 부분 행렬로 분할

각 블록에 대해 MAC 연산 수행

부분 연산 결과를 누적하여 최종 점수 계산

이 방법은 데이터 처리 단위를 조절하여 캐시 메모리 활용도를 높이는 데 도움이 될 수 있습니다.

3) 메모리 사용 최적화

대규모 행렬에서는 연산 속도뿐 아니라 메모리 사용량도 중요합니다.

불필요한 행렬 복사 최소화

기존 배열을 재사용하여 임시 객체 생성 감소

데이터 자료형을 검토하여 필요한 정밀도에 맞는 메모리 사용

이를 통해 메모리 낭비를 줄이고 대규모 데이터 처리 효율을 높일 수 있습니다.

4) 병렬 처리(Parallel Processing)

서로 독립적인 여러 패턴이나 행렬을 동시에 처리하는 방법입니다.

패턴별 MAC 연산을 독립적으로 실행

CPU 멀티프로세싱 또는 GPU 연산 활용 검토

여러 테스트 데이터를 동시에 처리하여 전체 실행 시간 단축

다만 작은 행렬에서는 병렬 처리에 필요한 작업 분배와 통신 비용이 오히려 더 클 수 있으므로, 데이터 규모가 충분히 큰 경우에 적용하는 것이 적절합니다.

5) 최적화 적용 우선순위

현재 프로젝트의 구조와 연산 특성을 고려하면 다음 순서로 최적화를 검토할 수 있습니다.

NumPy를 활용한 벡터화로 반복문 실행 부담 감소

블록 연산을 통한 대규모 행렬 처리 효율 개선

불필요한 메모리 복사와 임시 배열 생성 최소화

독립적인 패턴이 대량으로 입력되는 경우 병렬 처리 적용 검토

위 전략은 향후 대규모 데이터 처리를 위한 개선 방향이며, 현재 프로그램에 모두 구현된 기능은 아닙니다.

### 8-2. 측정 결과

최종 실행에서 측정한 결과입니다.

| 행렬 크기 | MAC 연산 횟수 | 평균 실행 시간 |
|---|---:|---:|
| 3×3 | 9 | 0.000430 ms |
| 5×5 | 25 | 0.001004 ms |
| 13×13 | 169 | 0.005466 ms |

### 8-3. 성능 분석

행렬 크기가 증가하면서 MAC 연산 횟수도 증가했습니다.

- 3×3 행렬: 9회
- 5×5 행렬: 25회
- 13×13 행렬: 169회
- 25×25 행렬: 625회

실제 실행 시간도 행렬 크기가 커질수록 증가하는 경향을 확인했습니다.

이는 모든 행과 열을 순회하는 이중 반복문 구조와 일치하며, 이론적인 시간 복잡도 O(N²)을 이해하는 데 도움이 됩니다.

단, 실제 실행 시간은 컴퓨터의 성능이나 실행 환경에 따라 달라질 수 있습니다.

## 9. 문제 해결 및 개선 과정

### 9-1. MAC 함수의 행렬 크기 일반화

초기에는 3×3 행렬만 처리할 수 있는 구조였지만, 다양한 크기의 행렬을 처리할 수 있도록 반복문의 범위를 행렬 크기에 맞게 변경했습니다.

이를 통해 동일한 MAC 함수를 3×3, 5×5, 13×13, 25×25 행렬에 사용할 수 있게 되었습니다.

### 9-2. JSON 필터 가중치 수정

초기 JSON 자동 테스트에서는 일부 패턴의 Cross 점수와 X 점수가 같거나 매우 비슷하게 계산되어 UNDECIDED 결과가 발생했습니다.

이는 MAC 연산 자체의 오류가 아니라 필터의 가중치가 특정 패턴과 충돌했기 때문이었습니다.

문제의 원인을 분석한 후 각 크기의 필터에서 중앙 가중치를 조정했습니다.

- `size_5`의 Cross 필터 중앙 가중치: 0.9 → 0.1
- `size_13`의 X 필터 중앙 가중치: 7.5 → 0.1
- `size_25`의 Cross 필터 중앙 가중치: 4.9 → 0.1

수정 후 JSON 자동 테스트 6개가 모두 PASS로 변경되었습니다.

이 과정을 통해 프로그램의 연산 로직과 테스트 데이터의 설계 문제를 구분하는 것이 중요하다는 점을 확인했습니다.

## 10. 결론 및 핵심 원리 요약

이번 프로젝트를 통해 Python으로 행렬 연산을 구현하고, JSON 파일을 이용하여 테스트 데이터를 관리하며, 자동 테스트와 성능 측정을 수행하는 과정을 경험했습니다.

핵심 원리는 다음과 같습니다.

1. **MAC 연산**: 두 행렬의 같은 위치에 있는 원소를 곱하고 그 결과를 누적하여 점수를 계산합니다.
2. **필터 비교**: 각 필터의 MAC 점수를 비교하여 입력 패턴과 더 유사한 필터를 선택합니다.
3. **JSON**: 데이터를 키와 값의 구조로 저장하고 프로그램에서 불러와 활용하는 데이터 형식입니다.
4. **데이터 검증**: 행렬의 크기와 자료형을 확인하여 잘못된 데이터로 인한 오류를 방지합니다.
5. **자동 테스트**: 정답 라벨과 예측 라벨을 비교하여 프로그램의 동작을 검증합니다.
6. **시간 복잡도**: N×N 행렬의 모든 원소를 순회하므로 MAC 연산의 시간 복잡도는 O(N²)입니다.

최종적으로 3×3, 5×5, 13×13, 25×25 행렬을 대상으로 MAC 연산을 수행했으며, JSON 자동 테스트 6개에서 100% 통과율을 확인했습니다.

이를 통해 단순한 계산 기능을 구현하는 것뿐만 아니라 데이터 관리, 검증, 테스트, 성능 분석까지 포함하는 프로그램 개발 과정을 경험했습니다.
